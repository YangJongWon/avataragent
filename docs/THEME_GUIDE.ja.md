# テーマ作成ガイド

テーマはオフィスの**背景**、**小物**、**社員キャラクター**を変えます。キャラクターには基本の動き（立つ、歩く、座る）と、仕事中に起きることに合わせた**イベント別の動き**（ヘルプ依頼、差し戻し、タスク承認など）があります。さらに、条件によって変わる**頭上のアイコン・セリフ**、**ふれあいメニュー**（あいさつするなど）、**イベントへの反応**、**移動経路**、ハロウィンのような**季節バリエーション**を加えられます。各部分は別々に定義し、定義しなかった部分はアプリの既定値を使います。アプリに入っているドットのオフィスも、こうしたテーマの1つです。

作ったテーマは `.zip` ファイル1つで共有します。誰でもインストールできるよう、インストール時にファイルと CSS を検査し、安全なものだけを受け入れます。

インストールしたテーマは、テーマタブで **すべてのオフィスで使う** を押すと会社共通のテーマになり、すべてのオフィスに適用されます（オーナーのみ）。特定のオフィスだけ違う飾り付けにするには、そのオフィスで **このオフィスだけで使う** を押し、戻すときは **共通テーマに従う** を押します。

テーマはオフィスの場面だけでなく、**サイトの画面**（上部バー、タブ、パネル、ボタン、フォント、角、ページの背景）も変えます。既定では見ているオフィスのテーマに従い、オーナーがテーマカードの **サイトで使う** を押すと、オフィスに関係なくそのテーマに固定されます。**オフィスのテーマに従う** で元に戻します。

## 作り方

### 1. テーマスタジオ（おすすめ）

アプリの **テーマ → テーマを作る** で、JSON を直接書かずに作れます。

1. **基本情報**：名前、id（英小文字・数字・ハイフン 2〜40文字）、ライセンスを決めます。
2. **背景**：1000×480 の画像をアップロードします。複数枚を重ねられ、「前」と指定したレイヤーは机の前板のように社員を隠します。
3. **場所を決める**：役割ごとの席、休憩場所、ドアをプレビューでクリックして指定します。ボード・資料室・金庫・保管庫の領域はドラッグして描きます。指定しなかった場所は既定のオフィス配置に従います。
4. **キャラクター**：スプライトシートをアップロードしてフレームの大きさを入力すると、格子状に切り分けられます。動きを選んでマスをクリックすると、その動きにフレームが入ります。
5. **色と CSS**（任意）
6. プレビューで動きを切り替えながら確認し、**zip をダウンロード** または **すぐにインストール** を押します。

スタジオはサーバーと同じ検査を行うので、「エクスポートの準備ができました」と表示されればインストールも通ります。

### 2. 手作業で作る

次の構成でファイルを集めて zip にまとめます。フォルダーごとまとめても構いません。

```text
theme.json        マニフェスト（必須）
preview.png       ギャラリーのサムネイル（必須、500×240 推奨）
assets/*.png      背景レイヤー、スプライトシート、ポートレート
theme.css         カスタム CSS（任意）
LICENSE.txt       ライセンス全文（任意）
```

## 動きの一覧

キャラクターに **`idle`（立つ）が1つあるだけでも** テーマは動きます。ない動きは矢印をたどって最も近い動きで代わりに表示します。

| 分類 | 動き | いつ | ない場合 |
|---|---|---|---|
| 基本 | `idle` | 立っているとき（必須） | — |
| | `walk` | 歩いているとき | idle |
| | `sit` | 席にいるとき | idle |
| | `back` | 後ろ姿：部屋の奥へ歩くとき、ボード・本棚・ドアの前に立っているとき | idle |
| | `walk_back` | 後ろ姿で歩くとき | walk |
| 社員の状態 | `working` | 仕事中 | sit |
| | `collaborating` | 協業中 | working |
| | `waiting` | 順番待ち | idle |
| | `awaiting_approval` | ユーザーの承認待ち | waiting |
| | `help_requested` | ヘルプを依頼したとき | troubled |
| | `paused` | 一時停止 | idle |
| | `error` | エラー | panic |
| 表情 | `smile` | 笑顔 | idle |
| | `focus` | 集中 | working |
| | `sweat` | 冷や汗 | troubled |
| | `troubled` | 困り顔 | idle |
| | `panic` | 慌てる | sweat |
| | `thanks` | 助けてもらったとき | smile |
| | `celebrate` | お祝い | smile |
| 仕事の瞬間 | `step.brief` | 課題受付の段階を始めるとき | working |
| | `step.research` | 資料調査を始めるとき | focus |
| | `step.draft` | 下書きの作成を始めるとき | working |
| | `step.review` | レビューを始めるとき | focus |
| | `review.rejected` | 自分の成果物が差し戻されたとき | troubled |
| | `task.approved` | タスクが終わったとき（全員） | celebrate |
| | `budget.exceeded` | 予算が尽きたとき | panic |

仕事の瞬間の動きは約2.4秒再生した後、元の状態に戻ります。歩く・揺れる・お祝いのジャンプのような動きはアプリが加えるので、フレームは2〜3枚で十分です。

## theme.json

```json
{
  "format": "avataragent-theme",
  "version": 1,
  "id": "cozy-office",
  "themeVersion": "1.0.0",
  "name": "ほっこりオフィス",
  "author": "作者名",
  "license": "CC-BY-4.0",
  "description": "あたたかな木目のオフィス",
  "preview": "preview.png",
  "scene": {
    "layers": [
      { "image": "assets/room.png", "x": 0, "y": 0 },
      { "image": "assets/desk-fronts.png", "x": 0, "y": 0, "front": true }
    ],
    "scaleMode": "linear",
    "seats": { "manager": { "x": 400, "y": 194 } },
    "lounge": { "manager": { "x": 862, "y": 342 } },
    "door": { "x": 805, "y": 248 },
    "spots": { "board": { "x": 260, "y": 14, "w": 280, "h": 86 } }
  },
  "characters": [
    {
      "id": "mina",
      "name": "ミナ",
      "sheet": "assets/mina.png",
      "frames": {
        "f0": { "x": 0, "y": 0, "w": 64, "h": 96 },
        "f1": { "x": 64, "y": 0, "w": 64, "h": 96 }
      },
      "anchor": { "x": 0.5, "y": 1 },
      "head": { "x": 0.5, "y": 0.05 },
      "hand": { "x": 0.8, "y": 0.6 },
      "scale": 1.5,
      "states": {
        "idle": { "frames": ["f0"] },
        "walk": { "frames": ["f0", "f1"], "fps": 8 },
        "task.approved": { "frames": ["f1"], "loop": false }
      },
      "portraits": { "smile": "assets/mina-smile.png" }
    }
  ],
  "tokens": { "accent": "#e07a5f" },
  "css": "theme.css"
}
```

- **座標**：オフィスは 1000×480 の座標系です。席・休憩場所はキャラクターの**足**の位置です。
- **役割**：`manager`、`researcher`、`writer`、`reviewer`。指定しなかった役割と場所は既定の配置を使います。
- **`spots`**：ボード（`board`、タスクのタイトルがここに書かれます）、資料室（`shelf`、調査のときに歩いて行きます）、金庫（`safe`、利益が表示されます）、保管庫（`archive`、完了した書類が飛んで行きます）。
- **仕事スペースと休憩スペース**（任意）：背景レイヤーに `"area": "work"` または `"area": "lounge"` を付けて2つのスペースの背景を別々に決め、`scene.areas` に各スペースの領域を書きます（例：`"areas": { "work": { "x": 0, "y": 0, "w": 760, "h": 480 }, "lounge": { "x": 760, "y": 0, "w": 240, "h": 480 } }`）。チームの色は仕事スペースの背景にだけ付き、両方のスペースがあると社員はドアを通らずに席と休憩場所の間を直接行き来します。スペースを決めなければ、最初のレイヤーが部屋全体として扱われます。
- **`anchor`**：フレーム内で足が着く位置（0〜1）。既定値は下の中央です。
- **`head`**：フレーム内の頭のてっぺんの位置（0〜1）。社員の AI モデル会社の帽子がここに載ります。
- **`scaleMode`**：ドット絵は `nearest`、イラストは `linear`。
- **`tokens`**：サイト画面の色。色の値（#hex、rgb()、hsl()）だけを受け付けます。下の[サイトの画面](#サイトの画面-tokens-site任意)をご覧ください。
- **`hand`**：フレーム内で物を持つ手の位置（0〜1）。既定値は `{ "x": 0.8, "y": 0.6 }` です。
- **`portraits`**（任意）：表情ごとのポートレート（`normal`、`smile`、`focus`、`sweat`、`troubled`、`panic`、`thanks`、`celebrate`）。ヘルプ依頼のウィンドウと社員カードに表示されます。ない表情は動きと同じ順序で代わりを探し（例：`thanks` → `smile`）、それでもなければ `normal`、それもなければ立っているフレームを表示します。128×128 程度を推奨します。
- **キャラクターの割り当て**：社員管理で社員ごとにテーマのキャラクターを選べます。選ばなかった社員には役割の順に割り当てられます（マネージャー → 1人目のキャラクター、…）。

### パーツと衣装（`parts`、`outfits`、`dress`、任意）

キャラクターを頭・胴体・脚のレイヤーに分け、着替える服を決められます。

```json
{
  "id": "mina",
  "sheet": "assets/mina-legs.png",
  "parts": { "body": "assets/mina-body.png", "head": "assets/mina-head.png" },
  "outfits": [
    { "id": "casual", "name": { "ko": "캐주얼", "ja": "カジュアル", "en": "Casual" }, "parts": { "body": "assets/mina-cardigan.png" } },
    { "id": "pumpkin", "name": "かぼちゃの服", "sheet": "assets/mina-pumpkin.png" }
  ],
  "frames": { "...": "..." }
}
```

- **`parts`**：`legs`、`body`、`head` のパーツシート。`sheet` の上に脚 → 胴体 → 頭の順に重ねます。すべてのパーツシートは `sheet` と**大きさとフレーム配置がまったく同じ**で、自分のパーツ以外は透明である必要があります（LPC のような着せ替え人形方式）。パーツを使うと `sheet` は一番下のレイヤー（脚や素体）になります。
- **`outfits`**：キャラクターごとに16着まで。`parts` はそのパーツだけを変え、`sheet` は絵全体を変えます（このときはキャラクターのパーツは重ねず、衣装の `parts` だけを重ねます）。衣装の絵もキャラクターのフレーム配置をそのまま使います。
- 衣装の id はキャラクター同士で同じ言葉を使います（`casual`、`suit`…）。社員管理の **衣装** で社員ごとに選ぶと、その id の衣装があるキャラクターだけが着替えます。
- **`dress`**（テーマの最上位、32個まで）：条件に応じて自動で着替えます。上から読み、**そのキャラクターにある衣装**を指す最初の規則が、社員に選んだ服より優先されます。合う規則がなければ社員に選んだ服、それもなければ既定の服です。

```json
"dress": [
  { "when": { "place": "lounge" }, "outfit": "casual" },
  { "when": { "weekdays": [5] }, "outfit": "casual" }
]
```

季節バリエーションに `dress` を入れると（例：ハロウィンに `pumpkin`）、その期間はその規則を先に読みます。ポートレートは衣装に関係なく同じ絵を使います。

### モデルごとの姿（`forms`、任意）

スタッフのモデルによってキャラクターの姿そのものを変えられます（スーパーサイヤ人1・2・3・4のように）。キャラクターごとに、等級別（`tiers`）とモデル id 別（`models`）で決めます。

```json
"characters": [{
  "id": "goku",
  "sheet": "assets/goku.png",
  "forms": {
    "tiers": {
      "1": { "name": "초사이언 1", "sheet": "assets/goku-ssj1.png" },
      "2": { "name": "초사이언 2", "sheet": "assets/goku-ssj2.png", "accessories": [{ "image": "assets/spark.png", "at": "head" }] },
      "3": { "name": "초사이언 3", "parts": { "head": "assets/goku-ssj3-hair.png" } }
    },
    "models": {
      "claude-opus": { "name": "초사이언 4", "sheet": "assets/goku-ssj4.png", "portraits": { "normal": "assets/goku-ssj4-face.png" } }
    }
  }
}]
```

- モデル別の姿があれば、そのモデルは等級別の姿の代わりにそれを使います。どちらもなければいつもの姿です。
- `sheet` はスプライト全体を置き換え（衣装より優先）、`parts` は衣装の上で一部位だけ替えます。どちらもキャラクターの `sheet` と同じフレーム配置にします。
- `accessories` があると、その姿ではテーマの小物（`accessories`、`modelAccessories`）の代わりにこのリストを使います。なければテーマの小物のままです。
- `portraits` があると会話の肖像も変わります。`name` はスタッフ管理のモデル選択カードに表示されます。
- `sheet`、`parts`、`accessories`、`portraits` のどれか一つは必要で、モデル別の姿はキャラクターごとに64個までです。

### モデル会社の小物（`accessories`、任意）

社員の AI モデル会社と等級は、既定ではドットの帽子で表示されます。テーマが小物を決めると、帽子の代わりに小物を重ねます。

```json
"accessories": {
  "claude": {
    "1": [{ "image": "assets/orange-ribbon.png", "at": "head", "x": -14, "y": 4 }],
    "2": [{ "image": "assets/cape-pattern.png", "at": "head", "x": 0, "y": 40 }],
    "3": [{ "image": "assets/star-wand.png", "at": "hand", "x": 6, "y": -12 }]
  },
  "*": { "1": [{ "image": "assets/hairpin.png", "at": "head" }] }
}
```

- キーはモデル会社の id（`claude`、`gpt`、`grok`、`gemini`、自分で追加した会社の id）で、`*` はそれ以外のすべての会社です。
- 等級は積み重なります。3等級のモデルは1・2・3等級のレイヤーをすべて重ねます。
- 等級の数は決まっていません。キーは1〜99の等級の数字で、モデル・APIキー画面で4等級以上を作ればその数字をそのまま使えます。テーマにない等級は、下で最も近い等級に従います（`forms.tiers`、`accessoryLabels.tiers` も同じ）。たとえば1・2・3だけを決めたテーマでは、5等級のモデルは3等級の姿になります。
- `at` は `head`（頭のてっぺん）または `hand`（手）、`x`・`y` はその点からずらすピクセル（±512）、`scale` は倍率です。画像は中央を基準に付きます。
- 会社・等級ごとにレイヤー8個、会社は16社まで決められます。小物セットのない会社はドットの帽子をかぶり、セットはあってもその等級にレイヤーがなければ何も身に着けません。
- テーマスタジオにはまだ小物の編集画面がありません。スタジオでダウンロードした zip の `theme.json` に直接追加してください。

#### モデルごとの小物（`modelAccessories`、任意）

特定のモデルだけ別の小物にするには、モデル id で指定します。

```json
"modelAccessories": {
  "claude-opus": [{ "image": "assets/gold-crown.png", "at": "head", "y": -6 }],
  "gpt-pro": [{ "image": "assets/star-wand.png", "at": "hand", "x": 6, "y": -12 }]
}
```

- キーはモデル id（`claude-opus`、`gpt-pro` など。モデル・APIキー画面で追加したモデルの id も使えます）です。
- モデルごとの小物があると、そのモデルは会社・等級の小物の代わりにこのリストだけを使います（等級ごとに積み重なりません）。
- レイヤーの形式は `accessories` と同じで、モデルごとに8個、64モデルまで決められます。シーズン変形にも入れられます。

#### 小物の説明（`accessoryLabels`、任意）

スタッフ管理の「モデルを選ぶ」でこのテーマを選ぶと、ドットの帽子の説明の代わりにテーマが書いた説明が表示されます。

```json
"accessoryLabels": {
  "summary": { "ko": "최상위 모델은 별 마법 지팡이를 들어요.", "en": "Top-tier models hold a star magic wand." },
  "companies": { "claude": "주황 리본", "*": "머리핀" },
  "tiers": { "1": "리본", "2": "리본 + 망토", "3": "리본 + 망토 + 지팡이" },
  "models": { "claude-opus": "황금 지팡이" }
}
```

- `summary` はモデル選択の上に出る一行の説明（200文字）です。
- `companies` は会社名の横に付く説明（60文字）で、`*` はそれ以外の会社です。
- `tiers` は等級ごと、`models` はモデル id ごとの説明（60文字）で、モデルカードに表示されます。モデルの説明があれば等級の説明より優先します。
- 各文言は文字列か、言語ごと（`ko`、`en`、`ja`、`zh`）のオブジェクトで書けます。

## サイトの画面（`tokens`、`site`、任意）

オフィスの外側の画面の見た目です。決めなかった値は既定の見た目を使います。

```json
"tokens": { "topbar": "#5a3f33", "topbarInk": "#fff8ee", "tab": "#f7e9d6", "note": "#ffe6b8" },
"site": {
  "font": "rounded",
  "radius": 8,
  "background": { "image": "assets/paper.png", "repeat": true }
}
```

| 色トークン | 使われる場所 |
|---|---|
| `bg` | ページの地 |
| `paper` | パネル・カードの地 |
| `surface` | ボタン・入力欄の地 |
| `ink`、`muted` | 文字、薄い文字 |
| `line` | 枠線と影 |
| `topbar`、`topbarInk`、`topbarLine` | 上部バーの地、文字、下の枠線（メニュータブは地と文字を混ぜた色） |
| `tabBar`、`tab` | オフィスタブの列の地、パネル内のタブ |
| `yellow` | 選択されたタブ |
| `note`、`hover` | 選んだ項目・メモ、マウスを乗せた項目 |
| `accent`、`primary`、`green`、`red`、`blue` | 強調、メインボタン、利益・損失など |

- **`font`**：`default`、`rounded`（丸ゴシック）、`serif`（明朝）、`mono`（等幅）のいずれか、またはパッケージ内のフォントファイル `{ "file": "fonts/hand.woff2" }`。フォントファイルは WOFF2 のみ、4MB まで受け付けます。プリセットは端末にインストールされたフォントを使い、なければ既定のフォントで表示されます。
- **`radius`**：パネル・ボタン・タブの角の丸み（0〜20px）。既定は角張った 0 です。
- **`background`**：ページの背景画像。`repeat: true` なら元の大きさでタイル状に敷き、そうでなければ画面を覆うように引き伸ばします。
- 進行状態・緊急度のように意味の決まったバッジの色は変わりません。

## 条件の規則（`when`）

下の頭上表示、ふれあいメニュー、イベントへの反応、季節バリエーションはすべて同じ条件（`when`）を使います。書いた条件が**すべて**合う必要があり、リストはそのうち**1つ**が合えば十分です。値が1つだけのときはリストの代わりに文字列で書いても構いません。

| 条件 | 値 | 例 |
|---|---|---|
| `status` | 社員の状態：`idle`、`waiting`、`working`、`collaborating`、`awaiting_approval`、`help_requested`、`paused`、`off_duty`、`capacity_exhausted`、`error` | `["working", "collaborating"]` |
| `place` | `desk`（席）または `lounge`（休憩室） | `"lounge"` |
| `role` | `manager`、`researcher`、`writer`、`reviewer` | `["manager"]` |
| `character` | このテーマのキャラクター id | `["mina"]` |
| `expression` | 表情：`normal`、`smile`、`focus`、`sweat`、`troubled`、`panic`、`thanks`、`celebrate` | `"celebrate"` |
| `team` | オフィスのチーム：`dev`、`hr`、`mgmt`、`support`、`welfare` | `["dev"]` |
| `walking` | 歩いている最中か | `false` |
| `hours` | [開始時, 終了時) 見ている人の現地時刻、深夜0時をまたいでも可 | `[22, 6]` |
| `weekdays` | 曜日 0（日）〜6（土） | `[0, 6]` |
| `dates` | ["MM-DD", "MM-DD"] 両端を含む、年をまたいでも可 | `["12-24", "12-25"]` |

規則のリストは**上から読み、最初に合った規則**を使います。具体的な規則を上に、広い規則を下に置いてください。

文言（`say`、`label`）は文字列1つで書くか、言語別に書きます：`{ "ko": "안녕하세요!", "en": "Hello!", "ja": "こんにちは!", "zh": "你好!" }`。見ている人の言語がなければ韓国語、それもなければあるものの中から1つを表示します。`say` に複数の文言を書くと、そのたびに1つを選んで話します。

## 頭上の表示（`emotes`、任意）

社員の頭上のアイコンと、ときどき言うセリフを決めます。テーマの規則をアプリの既定の規則より先に読みます。アプリの既定の規則は、ヘルプ依頼 `?`、承認待ち `!`、エラー `!`、一時停止 `II`、お祝い ⭐、感謝 💗、役割ごとの仕事アイコン、役割ごとの休憩アイコンです。

```json
"emotes": [
  { "when": { "place": "lounge", "walking": false, "hours": [12, 13] }, "icon": "🍱", "say": ["お昼おいしい～"], "every": 45 },
  { "when": { "status": "working", "character": "mina" }, "icon": { "image": "assets/coffee.png" } },
  { "when": { "status": "paused" }, "icon": null }
]
```

- `icon`：絵文字・短い文字（8文字まで）、`{ "text": "!", "color": "#e74c3c" }`（丸いバッジ）、または `{ "image": "assets/…png" }`（28px 以内に縮小して表示）。`null` ならアイコンを隠します。
- `say`：規則が合い始めたときに吹き出しで1回話します。`every`（秒、3〜3600）を書くと、規則が合っている間その間隔でまた話します。
- アイコンとセリフは別々に探します。アイコンは `icon` のある最初の規則から、セリフは `say` のある最初の規則から取ります。
- ヘルプ依頼のような重要な表示を変えるときは、ユーザーが分かるようにしてください。

## ふれあいメニュー（`interactions`、任意）

社員を右クリック（長押し）したメニューの下の方に、あいさつするなどの項目を加えます。この項目は**反応を見せるだけ**で、タスクやデータには触れません。アプリの既定で **あいさつする**（`greet`）があり、時間帯（朝・昼・夜・明け方）と社員の状態（仕事中、困っている）によってセリフと動きが変わります。

```json
"interactions": [
  {
    "id": "snack",
    "label": { "ko": "간식 주기", "ja": "おやつをあげる", "en": "Give a snack" },
    "when": { "place": "lounge" },
    "reactions": [
      { "when": { "hours": [15, 17] }, "state": "celebrate", "say": ["おやつの時間だ！"], "effect": "hearts" },
      { "state": "smile", "say": ["ありがとう！"] }
    ]
  },
  { "id": "greet", "hidden": true }
]
```

- `when` が合うときだけメニューに表示されます。合う反応が1つもなくても隠れます。
- `reactions` は上から最初に合った反応を使います。`state` は約2.4秒再生する動き、`effect` は効果です。
- 効果：`sparkle`（きらきら）、`hearts`（ハート）、`sweat`（汗）、`notes`（音符）、`confetti`（紙吹雪）、`zzz`（眠い）。
- アプリの既定の項目と id が同じならテーマのものに置き換わり、`"hidden": true` ならメニューから外します。

## 小物（`props`、任意）

家具を背景の絵に合成せず、1つずつ置きます。小物ごとに絵を変えたり季節バリエーションで差し替えたりでき、状態別の絵も置けます。

```json
"props": [
  { "id": "door", "image": "assets/door.png", "x": 881, "y": 66, "spot": "door", "states": { "open": "assets/door-open.png" } },
  { "id": "sofa", "image": "assets/sofa.png", "x": 800, "y": 262 },
  { "id": "desk-1", "image": "assets/desk.png", "x": 85, "y": 232, "front": true }
]
```

- `x`、`y` は絵の左上です。小物は背景レイヤーの上に書いた順で描かれるので、遠いものから書いてください。
- `front: true` なら社員の前に描かれます。同じ絵を複数の小物で使っても構いません。
- `spot` はその小物が受け持つ場所です（`board`、`shelf`、`safe`、`archive`、`door`）。場所の座標は引き続き `scene.spots` と `scene.door` が決めます。
- `spot: "door"` の小物に `open` 状態の絵があれば、社員が出退勤でドアを通るときに少しの間開いた絵を表示します。
- 状態の絵は基本の絵と同じ大きさで作り、同じ左上に重ねてください。小物ごとに8個まで置け、イベントへの反応の `prop` で切り替えます。

## イベントへの反応（`events`、任意）

オフィスでイベントが起きたときの社員の動き・セリフ・効果と小物の状態を決めます。アプリの既定の演出（はんこ、コイン、書類運び）はそのまま表示され、テーマが決めた動きがその上で再生されます。`"replace": true` ならそのイベントのアプリ既定の演出を消します。

```json
"events": [
  { "on": "agent.arrived", "say": ["出勤しました！"] },
  { "on": "task.completed", "when": { "role": "manager" }, "say": ["みんなお疲れさま！"], "effect": "confetti" },
  { "on": "review.rejected", "state": "panic", "say": ["やり直してきます…"], "replace": true },
  { "on": "value.recognized", "prop": { "id": "safe", "state": "open", "ms": 2000 } }
]
```

| イベント | いつ | 反応する社員 |
|---|---|---|
| `task.created` | タスクが登録されたとき | 登録に関わった社員（いなければ場面中央に効果） |
| `task.completed` | タスクが終わったとき | 席にいる全員 |
| `task.handed_off` | 次の段階に渡すとき | 渡す社員 |
| `review.approved` / `review.rejected` | レビュー通過 / 差し戻し | レビュアー / 差し戻された社員 |
| `approval.requested` / `approval.denied` | ユーザーへの承認依頼 / 修正依頼 | 該当する社員 |
| `agent.help_received` | 助けてもらったとき | 助けてもらった社員 |
| `value.recognized` | 利益が出たとき | 該当する社員 |
| `mail.received` / `inquiry.received` | メール・問い合わせの到着 | 担当の社員 |
| `budget.exceeded` | 予算が尽きたとき | 該当する社員 |
| `cost.recorded` | 費用がかかったとき | 該当する社員 |
| `agent.arrived` / `agent.left` | 出勤してドアから入るとき / 退勤で出るとき | その社員 |

- 1つのイベントに規則が複数あれば、社員ごとに最初に合った規則1つを使います。`when` の社員の条件は反応する社員が基準です。
- `prop` の `ms` はその状態を表示する時間（100〜10000、既定 1500）です。

## 移動経路（`scene.waypoints`、`scene.links`、任意）

社員は既定では目的地までまっすぐ歩きます。通る地点と接続線を決めると、その道に沿って歩きます（机の間の通路、ドアの前など）。

```json
"scene": {
  "waypoints": {
    "aisle-left": { "x": 40, "y": 368 },
    "aisle-mid": { "x": 380, "y": 368 },
    "lounge": { "x": 880, "y": 420 },
    "door-step": { "x": 930, "y": 250 }
  },
  "links": [["aisle-left", "aisle-mid"], ["aisle-mid", "lounge"], ["lounge", "door-step"]],
  "walkSpeed": 150
}
```

- 出発点から最も近い地点へ行き、接続線に沿って最短の道で目的地に最も近い地点まで行ってから、目的地へ向かいます。
- 目的地が最も近い地点より近いか、2つの地点がつながっていなければまっすぐ行きます。
- 経路を決めると、仕事スペースと休憩室の間の廊下（ドア）経由は使いません。地点は48個、接続は128個までです。
- `walkSpeed` は毎秒のピクセル（40〜600、既定 170）です。

## 季節バリエーション（`variants`、任意）

同じテーマを日付・曜日・時間によって一部だけ違って見せます（ハロウィン、クリスマス、金曜の夜…）。`when` には `dates`、`weekdays`、`hours` だけを使え、上から最初に合ったバリエーション1つが適用されます。オフィスの画面は1分ごとに確認し、バリエーションが変わると描き直します。

```json
"variants": [
  {
    "id": "halloween",
    "name": "ハロウィン",
    "when": { "dates": ["10-24", "10-31"] },
    "tokens": { "topbar": "#2b1a3d", "topbarInk": "#ffd9a8", "accent": "#ff7a1a" },
    "addLayers": [{ "image": "assets/cobweb.png", "x": 0, "y": 0, "front": true }],
    "props": [{ "id": "plant", "image": "assets/pumpkin.png", "x": 20, "y": 420 }],
    "wear": [{ "image": "assets/witch-hat.png", "at": "head", "y": -6 }],
    "emotes": [{ "when": { "place": "lounge" }, "icon": "🎃", "say": ["トリック・オア・トリート！"] }],
    "interactions": [{ "id": "candy", "label": "あめをあげる", "reactions": [{ "state": "celebrate", "effect": "confetti" }] }]
  }
]
```

| 項目 | 適用のしかた |
|---|---|
| `layers` | 背景レイヤー全体を置き換える |
| `addLayers` | 背景レイヤーの後ろに加える |
| `props`、`characters`、`interactions` | 同じ id は置き換え、新しい id は加える |
| `accessories` | モデル会社ごとに置き換える |
| `modelAccessories` | モデルごとに置き換える |
| `wear` | すべての社員がモデル会社の小物の上に重ねて身に着ける（ドットの帽子の代わり） |
| `emotes`、`events`、`dress` | テーマの規則より先に読む |
| `tokens`、`site` | 書いた値だけを変える（サイトの画面もその期間に変わる） |

### 期間別テーマ（会社の設定）

テーマそのものを丸ごと変えたいときは、テーマタブの下の **期間別テーマ** で期間（MM-DD 〜 MM-DD）とテーマを決めます（オーナーのみ）。その期間は、共通テーマに従うすべてのオフィスが予約したテーマで表示されます。個別にテーマを選んだオフィスはそのままです。テーマ内の季節バリエーションと一緒に使えます。

## カスタム CSS の規則

CSS はインストール時にサーバーが書き直します。

- すべての規則が**そのテーマを使うオフィスの中**にだけ適用されます。`:root`、`html`、`body` はオフィスの領域を指すように変わります。
- 消されるもの：`@import`、パッケージの外を指す `url()`（外部アドレス、`data:` を含む）、`image-set()`、`expression()`、`javascript:`、`position: fixed`。
- `z-index` は100までです。
- 承認・共有・モーダル・決済・キーの画面（`.approval*`、`.share*`、`.modal*`、`.billing*`、`.key*`、`.login*`）を狙ったセレクターは外されます。
- `@media`、`@supports`、`@keyframes`、`@container`、`@font-face`（パッケージ内のフォントのみ）は使えます。

## ローカル AI で絵を作る

ローカルの画像 AI（例：ComfyUI + SDXL 系のアニメモデル）を使えば、1人でもキャラクターと背景を作れます。

- **うまくいくもの**：キャラクターデザイン、表情のポートレート、立つ・座る・お祝いのような静止ポーズ、背景と小物。
- **難しいもの**：歩きのように連続するフレーム。フレームごとに服のしわや髪が変わって震えて見えます。フレームは2〜3枚に減らし、アプリが加える動きに任せてください。
- **同じキャラクターを保つ**：参照画像（IP-Adapter）とポーズの骨格（OpenPose）を一緒に使うと、複数のポーズでも同じ人に見えます。表情だけを変えるときは、画像編集モデルで顔だけを直すほうが安定します。
- **背景の除去**：キャラクターは透過 PNG である必要があります。背景除去のノード（BiRefNet、rembg など）を使ってください。
- **ライセンス**：使ったモデルのライセンスが成果物の共有を認めているか確認し、`CREDITS.txt` にモデル名を書いてください。

### リポジトリの生成パイプライン

公式サンプルテーマ「イラストオフィス」はこの方法で作りました。レシピ1つで背景、小物、キャラクター、表情のポートレート、モデル会社の小物をすべて描き、テーマの zip まで作ります。

1. [ComfyUI](https://github.com/Comfy-Org/ComfyUI) の Windows portable（NVIDIA）をダウンロードして展開し、チェックポイント（例：`animagine-xl-4.0.safetensors`）を `ComfyUI/models/checkpoints` に入れます。SDXL の場合、VRAM 8GB 以上を推奨します。
2. ComfyUI の内蔵 Python に背景除去のパッケージをインストールします：`python_embeded\python.exe -m pip install rembg onnxruntime`
3. ComfyUI を起動します：`python_embeded\python.exe -s ComfyUI\main.py --listen 127.0.0.1 --port 8188`
4. リポジトリのルートでレシピからテーマを作ります：
   ```
   <ComfyUI>\python_embeded\python.exe scripts/art/make_theme.py art/themes/illust-office/art.json
   ```
5. `art/build/<id>.zip` ができたら、アプリのテーマタブでインストールします。

レシピ（`art/themes/<id>/art.json`）にはキャラクターごとに外見（`look`）とシードを書き、ポーズと表情はすべてのキャラクターが共通で使います。同じシードと外見の説明を使うことで、ポーズが違っても同じ人に見えるようにします。生成結果は `art/build/<id>/raw` に保存され、もう一度実行すると変わったものだけを描きます。気に入らない絵は、レシピでシードを変えるか `--redo <キー>`（例：`--redo mina-idle`）で描き直します。

レシピの家具（`props`）はそれぞれ小物としてエクスポートし、背景レイヤーには壁と床だけが残ります。ドアに `"door": true` と `"states": { "open": { "swing": true } }` を書くと、閉じたドアの絵から開いたドアの絵を作ります（画像モデルは対応する開いたドアを描くのが苦手です）。`emotes`、`interactions`、`events`、`dress`、`paths`（`waypoints`、`links`、`walkSpeed`）はそのままパッケージに入り、`variants` の `props` と `wear` は絵を描いて入れます。

- **舞台の見た目**：`room.stage` の `wallStyle` は `stripes`（木目パネルの壁紙）、`glass`（ガラスの仕切り）、`panels`（金属パネルと光のライン）、`floorStyle` は `boards`（フローリング）、`carpet`（カーペットタイル）、`grid`（光る格子）です。スペース（`areas`）ごとに別々に決められ、`panels`・`grid` は `colors.glow` を光の色として使います。
- **衣装**：キャラクターに `"outfits": [{ "id", "name", "look" }]` を書くと、同じシードで服だけを変えて描き直し、同じフレーム配置の衣装シートを作ります。
- **パーツの分割**：キャラクターに `"split": { "head": 0.46, "legs": 0.76 }`（頭のてっぺんからの絵の高さの比率）を書くと、シートを脚（`sheet`）・胴体・頭のレイヤーに切り分けます。
- **ポーズごとのシード**：1つのポーズだけがおかしければ、`"poseSeeds": { "back": 8121 }` でそのポーズのシードだけを変えます（衣装にも使えます）。後ろ姿はよく崩れるので、ビルド後に `back` のフレームを必ず確認してください。
- **背景色**：銀髪のような淡い髪は、白い背景だと後ろ姿がぼやけて消えやすくなります。キャラクターに `"background": "dark gray background"` を書くと、そのキャラクターのポーズを単色のグレーの背景で描きます（背景は切り取ります）。

同じリポジトリの「コーポレートオフィス」（`corp-office`）と「SF オフィス」（`sf-office`）のレシピが、これらの機能の例です。
